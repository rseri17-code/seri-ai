The Operational Intelligence Publication Pack makes the frozen doctrine and reference architecture easier to inspect, share, and evaluate. It does not change the architecture, introduce new layers, or redefine terminology.

Start with the Doctrine for definitions and boundaries: [Operational Intelligence Doctrine v1.0](/wiki/operational-intelligence-canonical-doctrine).

Use the Reference Architecture for implementation-neutral contracts, schemas, state machines, governance, evaluation, and conformance: [Operational Intelligence Reference Architecture v1.0](/wiki/operational-intelligence-reference-architecture).

Inspect the live synthetic artifact in the Operations Room: [Operations Room](/investigation-room).

Reference asset matrix.

| Asset | Use it to evaluate | Primary audience | Format |
| --- | --- | --- | --- |
| Doctrine | Definition, boundaries, glossary, original contribution, and citations | Distinguished engineers, SRE leaders, AI architects | Wiki |
| Reference Architecture | Contracts, states, governance, evaluation, conformance, and implementation behavior | Platform architects, AI engineers, governance reviewers | Wiki and Markdown |
| Diagram Pack | Architecture flow, state machines, sequence, evidence graph, and replay loop | Architects, reviewers, visual learners | Markdown |
| Conformance Profile | Minimum object fields and pass/fail checks for independent implementations | Platform architects, AI engineers, SRE leaders, governance reviewers | Markdown |
| Decision Packet Example | Whether recommendations remain evidence-backed, reversible, and approval-bound | SREs, incident commanders, engineering managers | Markdown |
| OI-ROOM-001 Walkthrough | How the model behaves end to end on a synthetic investigation | Executives, operators, recruiters, founders | Markdown and PDF |
| Evidence Pack | What would prove, weaken, or falsify the doctrine's usefulness | Technical reviewers, practitioners, research-minded leaders | Wiki, Markdown, and PDF |
